# Sena Language & Region V1

Staff dashboard UI language is per authenticated user. Property operations stay in the property currency and timezone.

## Library

**next-intl** (App Router, TypeScript, ICU interpolation and plurals). Locale is **not** placed in the URL. `app.sena.ng/front-desk` stays that path.

Locales are loaded one at a time through dynamic `import()` so English users do not download French, Arabic, or other catalogs.

## Locales

| Code | Language | Direction |
| --- | --- | --- |
| `en` | English (canonical fallback) | LTR |
| `fr` | Français | LTR |
| `ar` | العربية | RTL |
| `sw` | Kiswahili | LTR |
| `yo` | Yorùbá | LTR |
| `ha` | Hausa | LTR |
| `ig` | Igbo | LTR |

Existing users with no saved language stay on English. Browser `Accept-Language` is never used to switch an account.

## Persistence

- Column: `users.locale` (`varchar(16) not null default 'en'`)
- Cookie `sena_locale` mirrors the staff language for first paint, PWA, and the offline page
- `PATCH /api/me` `{ "locale": "fr" }` updates **the signed-in user only**
- There is no admin control to change another person's language in V1

## Namespaces

`common`, `navigation`, `overview`, `reservations`, `calendar`, `frontDesk`, `rooms`, `housekeeping`, `guests`, `website`, `reviews`, `directBooking`, `payments`, `invoices`, `offers`, `channels`, `analytics`, `reports`, `staff`, `apps`, `billing`, `settings`, `setup`, `errors`, `statuses`

Catalogs live in `apps/dashboard/messages/{locale}.json`. Missing keys merge from English at load time. Operators never see key IDs.

## Language vs region

- **Language:** UI words for this staff member
- **Region (later):** how dates, numbers, and currency *look*
- Operational truth remains the **property** timezone and **property** currency
- Stay Connect remains **NGN**. Language never infers currency
- Device timezone is not used for arrivals, departures, or folios

## RTL

Arabic sets `dir="rtl"` and `lang="ar"`. Shell layout uses logical CSS (`start`/`end`). Reservation IDs, room numbers, emails, phones, currency amounts, and charts stay LTR via isolation. Brand marks and codes such as `SEN-QDDGU5` stay readable.

## What this release does not translate

- Public hotel websites (`stayconnect.sena.ng` and other tenant sites)
- Guest-facing emails (not trivially locale-aware today)
- User-generated content: guest names, property names, room names/numbers, notes, custom categories, invoice custom descriptions, staff names, guest messages
- Database enum values (mapped only in the `statuses` namespace for display)
- Another user's language

## Errors

API `code` values are mapped in `errors.codes` when present. English `error` text remains the transport fallback. The API error architecture is unchanged.

## Fonts

Inter remains the English UI face. Noto Sans (latin-ext) and Noto Sans Arabic are self-hosted through `next/font` as production-safe fallbacks for Yoruba diacritics, French accents, and Arabic.

## PWA

The saved language works in the installed app. `offline.html` reads `sena_locale` and shows a small built-in string table. Service worker caching of operational APIs is unchanged.

## Add a translation key

1. Add the English string to `apps/dashboard/messages/en.json` under the domain namespace.
2. Copy the same key into `fr`, `ar`, `sw`, `yo`, `ha`, and `ig`. Missing overlays still fall back to English at load time, but catalogs should stay complete.
3. Call `useTranslations('namespace')` and render `t('key')`. Interpolate with ICU: `t('nights', { count })`.
4. Never interpolate guest names, room numbers, or reservation IDs as translatable copy. Isolate those values with `ltr-isolate` / `isolateLtr()`.

## Add a locale

1. Add the code to `APP_LOCALES` and `LOCALE_META` in `apps/dashboard/src/i18n/config.ts`.
2. Add a loader in `apps/dashboard/src/i18n/messages.ts`.
3. Create `apps/dashboard/messages/{code}.json` covering every English key.
4. If the language is RTL, add it to `RTL_LOCALES`.
5. Extend the small copy table in `apps/dashboard/public/offline.html`.
6. Do not add a URL prefix. Staff routes stay `/front-desk`, not `/ar/front-desk`.

## Dates, numbers, and currency

Operational values stay on the **property** timezone (`Africa/Lagos` for Stay Connect) and **property** currency (`NGN`). Language never infers currency. Device timezone is not used for arrivals, departures, or folios. `useFormatter()` may preview locale-aware date/number *display* on Settings → Language & Region without changing stored amounts.
